# Contributing Guidelines

## Branching Policy
- **Main Branch:** Protected. No direct commits allowed.
- **Feature Branches:** Create a branch for every task (`feature/description` or `fix/description`).
- **Draft PRs:** Open a Draft Pull Request as soon as you start working on a branch. This allows for early feedback and visibility.

## Commit Requirements
- **Frequency:** Minimum of **one (1) substantive commit every 3 days**.
- **Content:** Each commit should represent a logical unit of work (e.g., a function, a component, or a fix).
- **WIP Commits:** If a task is not finished within 3 days, you MUST push a "Work In Progress" (WIP) commit showing at least 50% progress.
- **Accountability:** If no commit is pushed within the 3-day window, you must provide a valid reason/excuse in the team communication channel.

## Merging
- Only the Project Lead can merge Pull Requests into the `main` branch.
- A code review and an inspection check are required before any merge.
